# Published writing — what is already out there, and how the user writes

Covers anything the user publishes under their own name: LinkedIn posts, blog articles, conf
talks, newsletters, README/spec write-ups. **Log it here when it goes out.**

> ### ⚠️ Why this file exists — read before drafting ANY post
> **An agent that cannot see what the user has already published will re-publish the user's own
> thesis back at them.** The originating failure: a drafted post whose entire payoff paragraph
> restated the argument of a post published two months earlier — caught only because *the user*
> happened to remember. Nothing in the repo could have caught it, because the repo had no record
> of what had been said in public.
>
> An agent has perfect access to the user's *experience* (`profile/`) and zero access to their
> **published output**. Those are different corpora, and the second one is the one the audience
> has already read. Material that is fresh in the repo can be **spent** in public.

## The user's written voice, calibrated from their own published work

> ### ⭐ Voice is per-REGISTER, not per-person
> A single "here is how the user writes" note is wrong roughly half the time. The same person
> has **materially different registers** for different surfaces, and an agent that reuses one
> calibration for the other writes in a voice the user will not recognise.
>
> The clearest split in practice: **dictated/spoken answers** (application forms, screening
> questionnaires — often plain, no em-dashes, no semicolons, conversational) versus **written
> long-form posts** (short paragraphs, bullets, em-dashes, deliberate structure). Neither is
> "the" voice.
>
> **So: calibrate each register separately, from real samples of THAT register, and label which
> register each note describes.** A voice note with no register label is a trap.

## Standing rules for any future post

Non-negotiables, checked before anything is published. Add to this list every time a draft
nearly goes wrong.

- **No third-party names** — Golden Rule #9 applies to public writing exactly as it does to the
  repo. Not collaborators, not maintainers, not colleagues. Naming the user's **own employer**
  is fine.
- **No superlative claims that a third party can falsify** — "the only X", "the first Y". Check
  before writing; the correction lands in public.
- **No traction claims** (stars, users, downloads) and **no productivity multiples.**
- **A recruiting plug for the current employer is a CHOICE, not a default** — if the user is
  actively interviewing elsewhere, re-running one is a decision to make consciously.
- **Check the "already spent" section above before drafting.** This is the step the file exists
  for; do it first, not last.
