# Applications — ARCHIVE Index (closed applications)

Every **closed** application lives here — status `rejected`, `withdrawn`, `ghosted`, or
`not applied — skipped`. The folder sits next to this file
(`applications/_archive/<company-role>/`) and the row below is the row it had in
`applications/_index.md`, **moved verbatim** — nothing is rewritten, condensed, or deleted on
archival. The close-out procedure is `CLAUDE.md` §2.5 (Golden Rule #14).

> ⚠️ **This file is not optional history — it is where the search's memory lives.**
> The active index (`../_index.md`) holds only **open** applications, so:
>
> - **Golden Rule #12 (repeat-applicant gate)** — nearly every prior rejection is *here*, not
>   in the active index. **Scanning only `applications/_index.md` will report a clean slate
>   for a company that already said no.** The `new-application` skill's step 0 reads **both**.
> - **Golden Rule #13 (recurrence check — "has this failure class hit before?")** — the ledger
>   below is the answer surface. The `interview-debrief` skill reads it before naming a class.
> - **Any question about history** ("have I applied there?", "how many rejections?", "what
>   happened with X?") is answered from **both indexes**, never from the active one alone.
>
> **Nothing is ever deleted from here.** Archived rows and archived folders are **read-only
> history** — the same no-edit rule that protects a sent `cv.md`. The only permitted writes
> are (a) appending a post-mortem/diagnosis or a later recruiter reply to an archived
> `application.md`, (b) mechanical path/link repair, and (c) **un-archiving**: if a closed
> application reopens, move the folder *and* its row back to `applications/` and set a live
> status.

Status values: `rejected` · `withdrawn` · `ghosted` · `not applied — skipped`
(the live values — `interested` · `applied` · `screening` · `interviewing` · `offer` ·
`accepted` — live in [`../_index.md`](../_index.md)).

## Failure-class ledger — read this before naming a class (Golden Rule #13)

Only classes with a **written diagnosis** are listed. A rejection absent from this table has
no post-mortem on file — treat it as *undiagnosed*, not as *clean*. When a post-mortem names a
class, add the occurrence here in the same edit.

**A class that appears here with a correction already shipped, and then recurs, means the
previous fix did not hold** — escalate to a more mechanical guard (a gate, a read-back, a
required artifact), don't just add another note.
